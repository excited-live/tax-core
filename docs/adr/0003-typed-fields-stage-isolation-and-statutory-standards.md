# Typed Field Identifiers, 1:1 Stage-Test Isolation, and Minor-Unit Currency Threading

Tax calculation pipelines across jurisdictions involve hundreds of statutory rules, diagnostic breakdown paths, and boundary conditions. In early implementations, several recurring failure modes emerge: typos in raw diagnostic string literals (such as error paths or breakdown keys), bloated merged test suites that obscure which statutory rule failed, runtime safe-integer errors when non-integer major units are evaluated in percentage caps without currency scale, and fragile array-order assumptions on date-sensitive family rules.

We establish four non-negotiable statutory engine standards across all country modules (`@excited-live/tax/*`):
1. **Typed Field Identifiers**: All diagnostic breakdown paths, parameter keys, and validation error fields must be defined as typed enums (e.g. `ThAssessableField`, `ThExpenseField`, `ThAllowanceField`, `ThBracketField`, `ThTaxField`), and currency codes must be resolved via typed parameters (`parameters.currency`) rather than raw string literals. This is strictly enforced via an automated static checker script (`scripts/check-no-hardcoded-strings.ts`) in the CI verification pipeline.
2. **1:1 Stage-to-Test Isolation**: Every calculation stage file in `src/<jurisdiction>/stages/` must have a dedicated 1:1 unit test file in `src/<jurisdiction>/tests/` under 200 lines. Test files must never bundle multiple disparate categories or stages into a single merged test file.
3. **Currency-Threaded Minor Unit Arithmetic**: Percentage-based statutory caps and rates (`resolveCap`, `clampCap`) must thread the target ISO 4217 currency so conversions to and from integer minor units prevent floating-point drift and safe integer assertion failures on fractional amounts (e.g. satang or cents).
4. **Order-Independent and Validated Inputs**: Multi-item collections with statutory date cutoffs (e.g. birth years) must be sorted chronologically prior to evaluating index-based bonuses, and integer counts must be strictly validated against non-negative safe bounds.
