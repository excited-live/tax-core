# Per-Jurisdiction Subpath Exports with Country-Specific Statutory Inputs and a Standardized Result Envelope

Tax laws across countries diverge sharply at the input and intermediate calculation layers (Thailand uses Revenue Code Section 40(1)–(8) assessable categories, statutory expense deductions, and retirement allowance clusters; the United States uses filing statuses, AGI adjustments, standard vs. itemized deductions, preferential capital gains stacking, AMT, FICA/SECA, and 50 state regimes). Attempting to unify all countries behind a single universal input schema either drops statutory rules or forces consumers to pass meaningless fields.

We isolate each Jurisdiction under its own subpath export (`@trajectonomics/tax/th`, `@trajectonomics/tax/us`) with an optional `taxYear` defaulting to the latest constant year (`2026`), while sharing pure mathematical primitives in `src/core/` and returning a standardized `TaxResult<TBreakdown>` envelope across all jurisdictions. Consumers only bundle the jurisdiction they import, and higher-level applications can wrap the comprehensive statutory inputs without compromising statutory completeness in `@trajectonomics/tax`.
